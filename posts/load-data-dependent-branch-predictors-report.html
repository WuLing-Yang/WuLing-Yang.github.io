面向 Load-Data-Dependent Branch 的分支预测技术报告

BALL / LDBP / BOSS（待确认）与同类预测器的原理、对比与文献索引

版本：2026-08-18 · 面向对象：处理器微体系结构研究者（含 gem5/CBP 环境下的原型实现） 说明：本文所有结论均以论文原文/官方资料为准；无法从公开文献核实的条目已明确标注。

1. 背景：什么是 Load-Data-Dependent Branch

定义：一类条件分支，其走向（taken / not-taken）由一条（或几条）载入指令（load）从内存读回的数据值直接或间接决定。典型代码模式：

// 例 1：数组遍历，分支取决于随机元素值
for (i = 0; i < n; i++) if (a[i] > 16) ...   // bnez a4 ← lw a4, 0(a5)

// 例 2：图/链表遍历、哈希表查找
while (node) { if (node->flag) ...; node = node->next; }

为什么历史类预测器（TAGE 系）对这类分支几乎无能为力：

  1. 分支结果由数据决定，而数据（如数组元素、图节点属性）是随机的、与分支历史/路径历史相关性极低；
  2. 证据一：Seznec 的实验表明 256-Kbit TAGE 扩大到 1-Mbit，分支误预测只降低约 10%（LDBP 论文引用）；
  3. 证据二：TAGE-SC-L（CBP 2016 与 CBP 2020 锦标赛获胜者）的残余误预测高度集中在少数"hard-to-predict (H2P)"静态分支上（Bullseye 论文引用 Lin et al. 的工作：SPEC-INT 2017 单条 3000 万指令轨迹中，>50% 误预测来自 <10 个静态分支）；
  4. 现代深流水线（ROB 500+、取指宽度 10）下一次误预测代价可达上百条指令刷新，H2P 分支的权重被放大（RUNLTS 论文）。

关键洞察（LDBP 与 BALL 共同的核心）：分支依赖的数据值是随机的，但载入数据的地址往往是高度可预测的（数组步长、指针追逐、哈希表桶），因此可以：

  • 用地址模式先预测载入地址；
  • 用预测出的地址提前读数据缓存拿到（近似）真实的载入值；
  • 用载入值预计算出分支结果。

这一思路把"预测随机数据"转化为"预测规律地址"，是近十年该领域所有有效方案（LDBP、BALL、LVCP 等）的共同范式。

3. BALL 预测器（CBP2025 · Jun Fan）

3.1 出处

  • 论文：Jun Fan, "Branch Prediction via Load Value Prediction: A Case of BALL (Branch-ALU-Load-Load) Predictor", 6th Championship Branch Prediction (CBP2025), ISCA-52 workshop, Tokyo, 2025-06-21。
  • PDF：https://ericrotenberg.wordpress.ncsu.edu/files/2025/06/cbp2025-final56-Fan.pdf
  • 代码/幻灯片：https://ericrotenberg.wordpress.ncsu.edu/cbp2025-workshop-program/ （final56 条目）

3.2 定位与动机

BALL 是 TAGE-SC-L 的互补预测器（complementary predictor），只针对 TAGE-SC-L 误预测的"载入数据相关分支"。作者从 CBP2025 训练轨迹中 TAGE-SC-L 误预测最多的分支归纳出四类典型依赖模式（论文 Table 1–4）：

  1. 多载入 + 静态 ALU：分支依赖 3 条载入（固定地址 / 常量步长 / 指针追逐），ALU 为静态比较；
  2. 单载入 + 与零比较：condBr 依赖一条常量步长载入的取值与零比较；
  3. 浮点与零比较：载入值以浮点格式与零比较置标志位；
  4. 路径历史相关地址：载入地址与分支路径历史相关（需 E-VTAGE 预测地址）。

3.3 架构（成本明细见论文 Appendix A）

BALL = 64KB TAGE-SC-L + 128KB BALL，总预算 192KB（CBP2025 规则），各部件：

部件 作用 成本
TAGE-SC-L 主预测器（CBP2016 官方 64KB 版） 524,288 bits (64KB)
Architecture Register File (ARF) 提交阶段跟踪 32×64bit 整数 + 32×128bit FP + 标志位寄存器（模拟器无 ARF 接口，自建） 6,272 bits
Commit Queue (96 项) 记录提交指令的类/PC/源目寄存器，用于回溯构建依赖链 4,992 bits
BP Data Cache (128 set × 11 way) 模拟 L1 数据缓存：用预测出的地址读载入值（4B 粒度 valid） 798,336 bits (97.45KB)
Store Resolve Queue (8 项) 已解析未提交的 store 地址；命中则 BP Data Cache 查询视为 miss 392 bits
CondBR Chain Table (256 项) 记录 Branch-ALU-Load-Load 依赖链（1 分支节点 + 1 ALU 节点 + 4 载入节点） 47,104 bits (5.75KB)
Load Pattern Table (512 项) 载入地址模式训练：constant-stride（fixed/increment/wrap）、pointer-chasing、E-VTAGE 结果、in-flight 计数 90,624 bits (11.06KB)
ALU Pattern Table (512 项) ALU 比较操作（整型比较、整型与零、浮点与零）模式 2,560 bits
E-VTAGE（改自 8KB EVES） 用分支路径历史预测载入地址（仅 48-bit 地址） 54,130 bits (6.6KB)
合计 1,528,698 bits ≈ 186.6KB

注意：BP Data Cache 占了 97.45KB（总成本的一半以上）。作者指出：如果真实处理器允许分支预测器访问 L1 数据缓存，这块可以去掉，BALL 本体仅约 25.16KB。

3.4 工作机制（预测流水）

① 取指 PC 命中 CondBR Chain Table
   ↓
② 逐节点预测载入地址（优先级：E-VTAGE(路径历史) > wrap > fixed/increment > pointer-chasing）
   ↓
③ 用预测地址查 BP Data Cache（且 Store Resolve Queue 未命中）→ 得到预测载入值
   ↓
④ 用预测载入值 + ALU Pattern Table 的静态比较操作 → 预测标志位（flag）
   ↓
⑤ 用 taken[预测flag] 计数器（饱和到 ±3）→ 预测分支方向
   ↓
⑥ 与 TAGE 预测经 ball_tage_sel 计数器（0–255）仲裁：BALL 命中且被选 → 用 BALL；否则用 TAGE

地址预测的三种模式：

  • constant stride（含 fixed、increment、wrap 子模式）：预测地址 = last_commit_mem_va + in_flight_cnt × stride，wrap 时折返；
  • pointer chasing：预测地址 = 链上载入的预测数据值 + 常量 offset；
  • E-VTAGE：分支路径历史哈希预测地址（仅用于与路径历史相关的载入）。

训练触发：仅当提交的分支被 TAGE-SC-L 误预测时才尝试建立依赖链（链必须以载入为叶节点，最多 4 条载入 + 1 个 ALU），从而避免表污染、把存储集中到真正需要的分支上。

配置 MPKI CycWPPKI
64KB TAGE-SC-L 3.751 152.541
192KB TAGE-SC-L（等面积基线） 3.428 145.411
64KB TAGE-SC-L + 128KB BALL 3.542（-5.57% vs 64KB） 148.828（-2.43% vs 64KB）
  • 相对等面积 192KB TAGE-SC-L：整体 +3.32%/+2.35%（略差），但 fp 类负载 -9.85%/-3.20%（显著更好）；

  • 消融实验：收益最大来自 constant-stride 地址预测（-4.45% MPKI）与整型比较 ALU 预测（-3.20%）。

3.6 优点 / 缺点

优点

  • 精度极高（>96%）且"指哪打哪"：只在 TAGE 失手时出手，命中即准；
  • 地址模式设计（含 wrap 子模式、指针追逐）覆盖了数组/链表/哈希的常见形态；
  • 首次系统化支持浮点与零比较的载入相关分支。

缺点 / 局限

  • 延迟大：BP Data Cache 是串行双级访问（pointer-chasing 还要再翻一倍），CBP2025 模拟器又不允许在取指时提前触发载入（不像 LDBP 有 trigger load 时序机制），作者自述这是主要性能瓶颈；
  • 依赖模拟器提供提交级指令/寄存器信息（Commit Queue、ARF 需要自己维护，硬件开销不小）；
  • 对 compress/infra/media/web 类负载几乎没有收益（BALL 论文 Table 6）；
  • CBP2025 正式（secret）轨迹上整体收益为负、位列参赛者末位（官方闭幕报告），说明其收益对轨迹形态敏感（训练集中受益大的 int/fp 类未能在 secret 集中普遍复现）。

4. LDBP 预测器（UCSC · arXiv:2009.09064）

4.1 出处

  • 论文：Akash Sridhar, Nursultan Kabylkas, Jose Renau (UC Santa Cruz), "Load Driven Branch Predictor (LDBP)", arXiv:2009.09064 [cs.AR], 2020-09-18。
  • arXiv：https://arxiv.org/abs/2009.09064 （PDF：https://arxiv.org/pdf/2009.09064 ）
  • 机构镜像：https://escholarship.org/uc/item/1nd8j544

4.2 核心思想

与 BALL 同源但走得更远：载入数据随机、载入地址可预测（数组/图/哈希表的模板），于是：

  1. 用 stride 地址预测器识别"地址可预测"的载入（称 trigger load）；
  2. 在分支退休时，提前（ahead of time）触发未来的载入（真实载入而非预取，保证时序性，预取距离 = 覆盖在途指令 + 可变访存延迟）；
  3. 用触发载入读回的真实数据，沿 load-branch 反向代码切片（backward slice） 预计算分支结果；
  4. 预计算结果缓冲在 Branch Outcome Table (BOT)，分支取指时直接命中。

4.3 Load-Branch Chain 分类

  • Trivial chain：分支只依赖一条可预测载入（如 bnez a4），无中间运算——这类占大多数且最容易命中；
  • Complex chain：≥1 条可预测载入 + 若干简单 ALU 运算 + 分支（复杂 ALU 会被 LDBP 判无效）；
  • Load-Load chain：LD(donor)→op→LD(recipient)→...→br，供者载入可预测、受体载入不可预测，用供者值算受体地址。

链约束：载入与分支间最多 N 条简单 ALU（FSM 计算 ≤6 周期）、最多 N 条输入载入。

4.4 架构（两段式）

退休段（Retirement Block）：

  • Stride Predictor (SP)：识别可预测载入（PC tag、delta、置信度、last addr、tracking 位）；
  • Rename Tracking Table (RTT)：退休指令按逻辑寄存器索引，追踪链内操作数与载入指针；
  • Code Snippet Builder (CSB)：构建"载入→...→分支"的操作序列（仅在新链分配时更新，省功耗）；
  • Branch Trigger Table (BTT)：分支 PC 索引，链接其载入集与精度计数器（accuracy 归零即清空条目）；
  • Pending Load Queue (PLQ) / Load Outcome Register (LOR) / Load Outcome Table (LOT)：管理已触发的载入、地址范围匹配、载入数据缓冲。

取指段（Fetch Block）：

  • Branch Outcome Table (BOT)：每项一个 1-bit 结果队列（bot.outcome），取指命中时按 outcome_ptr 顺序弹出预测；
  • Code Snippet Table (CST)：由 CSB 拷贝的 FSM 代码片段，用 LOT 中的载入数据在取指端预计算未来分支结果（bot.cst_ptr 主动推进）。

Spectre 安全性：LDBP 明确设计为不做投机更新——退休段只在指令安全退休后更新；唯一投机更新的 LOR 在每次误预测 flush 时清空重建。作者强调 LDBP 本身不是新的投机泄漏源。

4.5 实验结果（ESESC 时序模拟，Zen 2 级核心配置，SPEC CINT2006 中精度<95% 的 hmmer/astar/gobmk + GAP 套件）

配置 结果
256-Kbit IMLI + 81-Kbit LDBP MPKI -22.7%，IPC +13.7%
150-Kbit IMLI + 81-Kbit LDBP MPKI -20%，IPC +13.1%（比 256-Kbit IMLI 还省 9.7% 硬件）
典型例子 向量遍历内核（随机 0/1 找 >0）：256-Kbit IMLI 上 IPC 提升 2.6×
  • 收益来源分解：大部分误预测由"可预测但及时"的触发载入消除（Fig. 16）；tc 等轨迹因载入步长频繁变化而收益受限；
  • 触发载入是真实载入（非预取），不会因预取丢弃而失效；与标准 stride 预取器/Perfect DL1 对比（Fig. 15）证明收益不来自"免费预取"；
  • 功耗：约 38.5% 执行时间处于低功耗门控模式；EPA 比 IMLI 低 55%（CACTI 6.0 估算）。

4.6 优点 / 缺点

优点

  • 时序性最彻底：真正提前触发载入、在取指端就有真实数据，预测质量不受"载入数据不可预测"限制；
  • 硬件开销小（81-Kbit）、功耗意识好、Spectre 安全、无需 ISA 修改；
  • 不占用主预测器预算——可替换/缩小主预测器（150K IMLI + LDBP 超越 256K IMLI）。

缺点 / 局限

  • 只适用于"载入地址可预测"的链；对地址本身随机的分支（如 tc 的部分模式）无效；
  • 需要较复杂的依赖链跟踪（RTT/CSB/BTT）与触发载入管理（LOR/LOT/PLQ），实现复杂度高于纯表方案；
  • 触发距离不当会污染缓存/浪费带宽；多路径分支（同一分支多条切片）未处理；
  • 只在 UCSC 自家 ESESC 上验证（Zen 2 模型），未参加 CBP 竞赛与主流框架横向对比。

6. 其他解决 Load-Data-Dependent Branch 的重要预测器

6.1 LVCP（CBP2025 季军 · 中科院计算所 ICT CAS · 香山团队）

  • 论文：Yang Man, Lingrui Gou, Yuhang Liu, Mingyu Chen, Yungang Bao, "LVCP: A Load Value Correlated Predictor for TAGE-SC-L", CBP2025。 PDF：https://ericrotenberg.wordpress.ncsu.edu/files/2025/06/cbp2025-final15-Man.pdf
  • 简介：给 TAGE-SC-L 增配一个 Load Value Correlated Predictor (LVCP)：
    • Load Marking Table：取指时识别缓存行内的载入指令（bitmap）；
    • Load Tracking Queue（16 项）：记录分支之前最近载入的位置，载入完成后回填其值；
    • Distant Load Buffer：按载入 PC 低位索引，捕捉超长距离的载入-分支相关（弥补队列容量不足）；
    • Correlation Table（banked）：用载入值哈希索引，训练"载入值→分支方向"映射；命中且置信度饱和才覆盖 TAGE；
    • H2P Branch Table (HBT)：识别 TAGE 高误预测分支（阈值≈MPKI>0.38），只对这些分支分配 LVCP 条目；
    • 训练在提交阶段进行（保证分支/载入的精确顺序）。
  • 结果（105 条训练轨迹、192KB 预算）：3.372 BrMisPKI / 144.076 CycWpPKI，相对基线 TAGE-SC-L 降低 2.07% BrMisPKI；CBP2025 官方排名 第 3（🥉），且官方闭幕报告显示其收益在 Perfect L1(I+D) 场景下进一步提升——印证"载入值类预测器受真实 L1 数据供给质量制约"。
  • 优点：纯表方案、实现/时序简单（并行访问、单周期仲裁）、训练基于提交（无投机更新，安全）；缺点：载入-分支距离超过队列+远端缓冲覆盖时失效；收益绝对值较小。

6.2 EXACT（CF 2010 · NCSU Rotenberg 组）

  • 论文：Muawya Al-Otoom, Elliott Forbes, Eric Rotenberg, "EXACT: Explicit Dynamic-Branch Prediction with Active Updates", ACM CF 2010。DOI: 10.1145/1787275.1787321
  • 思想：分支预测条目与"生产者载入的地址"关联（载入 PC+地址哈希为 ID）；store 指令写入被分支依赖的地址时，直接"主动更新"对应预测条目（active update），从而在载入发生前就更新好预测——解决了"store 改写载入值导致预测过时"的问题。
  • 定位：BALL/LVCP 相关工作的直接前身之一；"active update"机制至今仍是解决 store→load→branch 链过时问题的标准手段。

6.3 ABC（HPCA 2008 · NCSU Zhou Huiyang 组）

  • 论文：Hongliang Gao, Yi Ma, Martin Dimitrov, Huiyang Zhou, "Address-Branch Correlation: A Novel Locality for Long-Latency Hard-to-Predict Branches", HPCA 2008。DOI: 10.1109/HPCA.2008.4658629
  • 思想：观察到长延迟 cache-missing 载入的分支结果与其载入地址强相关（关键数据结构地址稳定）；用载入地址索引预测表，而不是用历史。
  • 意义：最早把"地址-分支相关"作为独立 locality 提出；LDBP、BALL、LdPHistPred 都引用它。

6.4 ARVI（HPCA 2003）

  • 论文：Lei Chen, S. Dropsho, D.H. Albonesi, "Dynamic Data Dependence Tracking and Its Application to Branch Prediction", HPCA 2003。DOI: 10.1109/HPCA.2003.1183525
  • 思想：把分支结果与物理寄存器值、逻辑寄存器索引、依赖链深度关联（Available Register Value Information）；依赖链终止于载入。
  • 意义：寄存器值相关分支预测的经典；BALL 的"依赖链"概念可追溯至此。

6.5 数据值相关的开山之作与编译器辅助方案

  • Heil, Smith & Smith（MICRO-32, 1999）："Improving Branch Predictors by Correlating on Data Values"——最早用数据值（而非历史）改进分支预测。（LDBP 论文 ref [32]）
  • Gonzalez & Gonzalez（PACT 1999）："Control-flow Speculation Through Value Prediction for Superscalar Processors"——用值预测预计算比较/分支。
  • SLB Predictor（HPCA 2013）：M.U. Farooq, Khubaib, L.K. John, "Store-Load-Branch (SLB) Predictor: A Compiler Assisted Branch Prediction for Data Dependent Branches"——编译器在编译期标记 store-load-branch 链中的 store，硬件按标记 store 的值计算分支条件。DOI: 10.1109/HPCA.2013.6522307（LDBP 论文 ref [14]；注意需软件/ISA 支持）。

6.7 Bullseye（CBP2025 · UBC）

  • 论文：Emet Behrendt, Shing Wai Pun, Prashant J. Nair, "Taming Wild Branches: Overcoming Hard-to-Predict Branches Using the Bullseye Predictor", CBP2025。 PDF：https://ericrotenberg.wordpress.ncsu.edu/files/2025/06/cbp2025-final36-Behrendt.pdf
  • 思想：不直接针对载入值，而是针对 H2P 分支的整体治理：
    • HIT（H2P Identification Table）：按执行/误预测计数自适应阈值，把少数（≤10 个）"顽固分支"标记为 H2P；
    • 试用期在 H2P cache 中对比 TAGE-SC-L 与两个分支专用感知机（本地哈希历史 + 折叠全局历史）的正面交锋；
    • 感知机胜出则"晋升"，并抑制 TAGE 对该 PC 的更新（防表污染）；失败则回退 HIT。
    • 159.3KB TAGE-SC-L + 28KB Bullseye：MPKI 3.4045 / CycWpPKI 145.09。
  • 意义：代表"H2P 专用子系统"路线——不依赖载入地址可预测性，通用性更强。

6.8 RUNLTS（CBP2025 冠军 · 名古屋工业大学 + 东京大学）

  • 论文：Toru Koizumi 等, "RUNLTS: Register-Value-Aware Predictor Utilizing Nested Large Tables", CBP2025。 PDF：https://ericrotenberg.wordpress.ncsu.edu/files/2025/06/cbp2025-final44-Koizumi.pdf
  • 思想：在 TAGE-SC-L 上做三点：(1) 寄存器值摘要（digest）注入统计修正器 SC——捕捉"寄存器/载入值 → 分支方向"相关（含载入值场景）；(2) 大规模 bimodal 表 + 新历史长度集合 + 新条目分配控制，充分利用 192KB 预算；(3) 改进 IMLI 权重 + call-stack 历史。
  • 结果（训练轨迹后半段）：BrMisPKI 3.197 / CycWpPKI 140.3，CBP2025 总冠军（🥇）。

6.9 值预测与载入值预测基座（供分支预测复用的基础设施）

  • Value locality / load value prediction：Lipasti, Wilkerson, Shen, "Value Locality and Load Value Prediction", ASPLOS 1996（ACM DOI）。
  • Efficient Load Value Prediction Using Multiple Predictors and Filters：Rami Sheikh & Derek Hower, HPCA 2019（IEEE DOI）——商用级载入值预测框架（含用求值后的载入值预测分支的组件）。
  • E-VTAGE / EVES：André Seznec, "Exploring Value Prediction with the EVES Predictor", CVP-1 2018（BALL 用它预测载入地址）。

9. 选型与实现建议（gem5 / CBP 视角）

  1. 想先低成本试水：LVCP 路线最合适——纯表结构（Load Marking Table + 跟踪队列 + 相关表），不依赖指令依赖链重建，改动集中在提交/取指两端；CBP2025 的 simulator framework（官方页面：https://ericrotenberg.wordpress.ncsu.edu/cbp2025/ ）提供了现成评测环境（192KB 预算、secret 轨迹验证）。
  2. 针对图遍历/数组类负载（GAP 风格）：LDBP 路线收益最大（-22.7% MPKI），但其"提前触发真实载入"需要时序模拟器支持（ESESC/Zen2 模型）；在 gem5 里实现需在 O3 提交端加依赖链跟踪（类似 BALL 的 Commit Queue + ARF）。
  3. 想在真实 gem5 O3 里验证"载入值相关"效果：gem5 取指级预测器接口拿不到载入值/载入地址，需要：
    • 提交端维护轻量 ARF（BALL 做法）或载入跟踪队列（LVCP 做法）获得"载入 PC/值/地址 → 分支"关系；
    • 预测端用分支 PC + 最近载入值哈希索引相关表；注意 gem5 的 fetch 与 commit 天然满足"提交信息先于下一次取指"，可做 LVCP 式（无投机更新）实现，安全性好、实现最稳。
  4. 组合策略（业界/竞赛共识）：TAGE-SC-L 为主 + H2P 识别 + 载入值辅助（RUNLTS 与 LVCP 的双料验证）；BALL 式"链重建"精度最高但延迟最贵，适合作为早期重定向/提前 flush 的补充（参考 Branch Runahead / TEA 的 flush 机制，而不是覆盖取指预测）。
  5. 注意时序陷阱：载入值类预测器的效果上限 = "载入值可得时间"；论文与 CBP2025 Perfect-L1 实验都证明：L1 数据访问延迟/缺失决定收益，设计时应评估独立读口/旁路数据缓存（BALL 的 BP Data Cache 就是为此自建的 97KB 结构）。
